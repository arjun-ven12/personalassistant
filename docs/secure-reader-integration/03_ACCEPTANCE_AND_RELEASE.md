## Hosted and release blockers

1. Current public Athena API responds 200 at `https://personalassistant-production-269b.up.railway.app/health` and 404 at `https://personalassistant-production-269b.up.railway.app/api/secure-reader/health` and `/api/secure-reader/admin.html`. Reader is **not deployed**.
2. Railway access is available to the existing Athena project. Its production API has no Reader TLS mail configuration, which is required for invitations and sign-in. Do not reuse unrelated engineering credentials.
3. The API volume is attached and the bounded child renderer passed a synthetic-PDF build check. Volume write/persistence after redeploy and the worker inside the hosted container are unverified. The worker is not an independent sandbox; this limitation must remain explicit.
4. The additive migration is the sole pending version in the live ledger, with no reported digest issue. It has not been applied to Neon. Athena's new image rejects pending migrations, and the old image rejects the newer ledger version after application. A migration-compatible rollback image must be prepared and tested.
5. No verified TLS mail delivery, Reader administrator bootstrap, real account, document import, or hosted session/revocation test occurred. The seven confidential PDFs were unavailable and remain unimported.
6. `v0.2.0-preview` release workflow is prepared but gated on a live ready Reader health endpoint and unauthorized document-list denial. No signed v0.2 APK or GitHub prerelease exists yet. The existing protected preview signing identity remains in GitHub Actions; no key was printed or copied.
