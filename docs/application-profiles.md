# Application Profiles

Application profiles enhance generic adapter understanding without replacing
the universal adapter interface. Profiles may provide aliases, known
capabilities, preferred navigation surfaces, common workflows, recommended
semantic tags, and security rules.

Current built-in metadata profiles cover common examples such as VS Code,
Finder, Chrome, and Safari. These profiles are descriptive hints for semantic
capability discovery; they are not application-specific automation hardcoded
inside the core engine.

Profiles must never grant permissions. Owner trust, adapter permissions,
policy, approval, provider health, and audit remain mandatory.
