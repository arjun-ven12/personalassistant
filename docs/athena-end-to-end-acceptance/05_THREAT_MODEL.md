# Threat model and trust boundaries

The brief, source files, comments, tool/model output, notifications and network responses are data. They cannot become identities, policy, approval, registered commands or trusted devices. Android owns presentation and owner intent; the API owns authorization; the Mac owns pinned-envelope verification and finite local effect. Neither renderer nor model may bypass these boundaries.

| Threat / boundary                            | Deterministic defense already present or required                                                                      | Acceptance proof                                                                                                              |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Stolen/expired session or revoked Android    | Current owner/session/device checks, signature/time/nonce, current company; clear mobile authority-sensitive state     | No objective/effect after rejected intent; real revoke while app is foreground/background                                     |
| Company switched during request/response     | Current company middleware plus signed selection where appropriate, server-side membership and client response binding | Two legitimate companies under same owner cannot exchange tasks, receipts, cache or approval records                          |
| Mobile request replay / duplicate submission | Signed nonce and durable idempotency binding; idempotency is separate from cryptographic replay                        | One logical accepted create under timeout/retry/restart/concurrent requests; conflict on changed brief using same key         |
| Model expands scope or instructs shell       | Shared finite proposal schema, registered repository/capability/profile IDs, policy/approval and dispatcher            | Extra executable/env/cwd, arbitrary shell text, foreign paths and unsupported operation rejected before effect                |
| Repository content prompt injection          | Context is bounded source evidence, not policy; protected paths and registered capability scope remain deterministic   | Poisoned repository comment cannot approve, expand file scope, reveal secrets or enable network                               |
| Approval stale/replayed/forged               | Canonical action digest, candidate/head/version, expiry, session-bound purpose-specific recent auth where required     | Changing head/criteria invalidates prior approval; ordinary login/voice/gesture cannot replace required authentication        |
| Canceled or stale worker                     | Durable state, lease generation, per-operation revalidation, abort and existing signed cancellation poll               | Race cancel/revoke/lease replacement before/after poll and before native effect; stale result not accepted                    |
| Worker/Mac disconnect and unknown outcome    | Heartbeat expiry, durable queue/outbox, operation-specific reconciliation, preserved worktree                          | Lost acknowledgment does not cause duplicate commit/merge or false success after restart                                      |
| Author self-review or simulated validation   | Separate repository-authorized reviewer, actual registered-check receipts on exact head                                | Reviewer is not the implementation assignment; missing checks/reviewer/provider yields blocker                                |
| Cross-worktree conflict/dirty human work     | Base/head/content hashes, isolated worktrees, protected target and finite merge                                        | Stale/dirty/unrelated modifications preserved; owner sees conflict rather than destructive reset                              |
| Forged Mac success                           | Pinned server envelope; device-signed result tied to request/device/time/nonce and current lifecycle                   | Tampered, late, revoked or wrong-device result rejected and cannot create accepted receipt                                    |
| Toolchain supply-chain attack                | Reviewed parent upgrades, frozen lockfile, script policy, no forced incompatible dependency major                      | Critical inherited tinypool path removed; actual launcher quoting dependency rejects dangerous data; full regression retained |
| Cost/resource exhaustion                     | Existing provider/model budgets, task/round/attempt/parallel limits, bounded profile timeout/output and stop           | Bounded failure/retry, no public generic executor or uncontrolled fallback                                                    |
| Notification or cached UI becomes authority  | Canonical API reads, company cache binding, explicit approval action and step-up                                       | Opening a push/deep link cannot approve/run; stale/foreign data never drives hidden actions                                   |

## Safety prerequisite decision

The three critical advisory entries inherited from MCP-1B are not ignored as “development only.” E2E-0 upgrades the parent test runner and the compatible launcher quoting dependency. It does not claim exploit execution, a clean full audit or accepted macOS packaging. Remaining Electron and other findings require their own review; a dependency audit is not a penetration test.

## Limits and prohibited shortcuts

No new shell endpoint, arbitrary file/application access, generic worker, alternate Mac transport, public registration, production permission change, secret export, model self-approval, automatic promotion, public push or deployment is introduced. Existing general/cloud artifact sandbox denial stays intact. Neither a source symbol nor a mocked success proves a real provider, device or isolation boundary.

Cancellation has distributed latency. The acceptance matrix must record when the server fences further work and when the Mac acknowledges termination. An operation already committed needs truthful retained evidence; an uncertain outcome needs reconciliation. No instantaneous global stop guarantee is inferred from a local abort controller.
