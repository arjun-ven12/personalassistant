## Recovery discipline

Record intent and operation IDs, repository/base/head, task lease generation, execution state, reviewer/validation IDs and last verified receipt before recovery. Select the smallest existing recovery operation only after current authority is revalidated. A reconnect is not an approval and a replacement worker is not permission to replay a mutation. Keep ambiguous outcomes blocked until operation-specific reconciliation establishes what happened.

The implementation slice in this run changes test/development tooling only. It intentionally does not claim to repair or accept all these distributed effect boundaries. Any observed runtime defect should become its own bounded next slice with test-first proof.
