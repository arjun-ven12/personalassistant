# Phase 28.2 Marketing, Brand and Creative Department

Updated: 2026-10-03.

## Campaign execution

Company-scoped campaigns reuse the Objective Engine, bounded deliverable DAG,
Agent Workforce, Agent OS, AIRouter, Universal Tool Gateway, Engineering
Delivery, existing memory store, policy, approvals and audit. Eight logical
marketing roles do not create resident model processes or another executor.
Production campaign creation and its Objective share the existing owner
portfolio transaction/advisory lock. Concurrent service instances converge on
one outcome; an audit failure rolls back both records.

Starting a campaign records the authenticated session used for autonomous
continuation. The server revalidates its expiry, owner/company membership,
private network and emergency-stop state. Workforce lifecycle events and
Engineering terminal events queue bounded coordinator passes. The existing
durable scheduler scans active campaigns for restart recovery and pending
approval decisions. No LLM polling is used. Progress stops at approval,
clarification, blocked work, cancellation or the review-only package.

Workforce specialists return a validated structured marketing result bound to
company, campaign, Objective, deliverable, agent and executed task provenance.
The result becomes an artifact directly, without another draft inference.
Existing assignment, model policy, capability and memory boundaries remain in
the Workforce/Agent OS path. Small campaigns retain the existing direct
AIRouter draft path. Explicit analytics windows and calendar inputs remain
owner clarification checkpoints.

## Exact review and approved memory

Artifacts follow DRAFT -> IN_REVIEW -> APPROVED/REJECTED, with SUPERSEDED for
replaced versions. Existing PolicyEngine and ApprovalService records bind the
artifact ID, version, content digest, company, campaign, Objective and reviewing
session to the canonical action digest. A new version requires a new approval;
an old decision cannot authorize changed content. Sensitive regulated claims
fail closed until a stronger registered recent-authentication review path is
available.

Only current approved brand facts can enter the existing company memory store.
Promotion is idempotent and retains exact source/version/digest evidence.
Retrieval rechecks the current approved source and stable fact content; drafts,
rejections, superseded sources, altered memory content and another company's
records are excluded. Future specialist and direct-draft contexts consume this
bounded approved memory.

## Tools, recovery and Engineering

Creative generation selects only reviewed finite WRITE tools with provider
idempotency/reconciliation support. The campaign persists its exact invocation,
tool, brief, media type and claim before gateway execution. Interrupted work
reuses a verified receipt or queries the same provider receipt. Missing,
indeterminate, failed or inconsistent evidence becomes OWNER_REVIEW_REQUIRED;
there is no blind retry or provider switch. Known-safe automatic write retry
is not implemented: owner review remains the conservative recovery boundary.
Cancellation preserves records and requests existing child cancellation; it
cannot recall an external operation already accepted by a provider.

Analytics uses reviewed company-scoped READ tools with explicit metric/time
windows and records invocation IDs. Landing-page work uses registered repository
IDs and deterministic Engineering child keys. Engineering owns its signed Mac
Agent, policy, validation and preview path. An internal verified preview is not
public publication authority. Public social publishing and paid activation are
unavailable.

## Evidence and economics

The coordinated sandbox test uses structured Workforce execution, exact
artifact approval, a real Universal Tool Gateway with finite sandbox creative
and analytics adapters, an Engineering preview mock, and a persisted review-only
launch package. Separate tests prove approved-memory retrieval, PostgreSQL
creation atomicity, version invalidation, restart/receipt recovery, cancellation
and cross-company denial. Sandbox assets/previews are not production evidence.

Campaign telemetry projects existing model ledger, exact gateway receipts and
linked Engineering model usage. Known USD totals and other currency minor-unit
totals remain separate; missing costs are explicit unknowns. No second ledger
or perfect campaign budget enforcement is added. Benchmark capture persists the
existing shared benchmark contract and available Engineering milestones/costs.
Unsupported action/tool/retry/intervention counters remain null. No live
landing-page speed benchmark or Codex comparison is claimed. The 3–7 minute
preview and 5–10 minute completion figures remain targets.
