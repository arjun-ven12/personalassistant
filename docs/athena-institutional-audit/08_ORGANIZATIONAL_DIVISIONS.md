# Proposed institutional divisions

> Audit date: 2026-10-26 · CONFIDENTIAL INTERNAL · Review draft v0.1
> Evidence scope: current workspace, including pre-existing uncommitted changes.
> Current implementation, test evidence, and proposed institutional design are distinguished below.

## Status and constitutional premise

All divisions below are **recommended institutional structures**, not claims of existing staffed departments, budgets, legal entities, clients, publications or research results. Current source has Agent Society organization/team/role records and company workforce departments; these are software coordination structures. The institutional model should map to them through explicit reviewed identifiers rather than create another agent registry or imply authority from a department name.

The proposed operating principle is common infrastructure, separate mandates, bounded access and accountable leadership. Every division has a human sponsor. AI roles perform scoped work with reviewable evidence; humans retain legal, ethical, security, publication and budget decision rights.

## 1. Athena Core / Agent OS

**Mission.** Make intelligence dependable across people, models and time by giving delegated work explicit identity, limits and memory.

**Mandate and responsibilities.** Own agent identity/lifecycle contracts, delegation semantics, scheduling interfaces, model abstraction, context and resource accounting. Maintain compatibility between the original Agent Registry, company assignments, Agent OS sessions and newer workforce/engineering runtime paths. Define task/result provenance and cancellation semantics.

**Existing assets.** `agents/`, `agent-workforce/`, `workforce-runtime/`, `agent-economy/`, `ai/`, shared contracts, original built-ins and reusable native/ECC-derived definitions. **Proposed human leadership:** Core Systems Lead and Runtime Maintainer. **AI roles:** engineering manager, planning, architecture and failure-analysis specialists. **Expertise:** distributed state machines, runtime design, TypeScript, PostgreSQL, model evaluation and secure API design.

**Decision rights and deliverables.** Propose versioned runtime/contract changes; approve internal compatibility plans within human governance; never self-grant tool permissions. Deliver runtime reference, lifecycle conformance suite, scheduling/recovery acceptance and cost attribution reports.

**Dependencies and access.** Works with Engineering for integration, Intelligence Lab for evaluation, Security for authority design. May read approved runtime source, sanitized task telemetry and scoped evaluation context. Must not access client repositories, private human records, provider secrets or unrelated company memory by default.

**Onboarding and measures.** Start with a read-only lifecycle walkthrough and fixture-backed task; assign a scoped repository and reviewer. Measure verified task outcomes, recovery success, duplicated dispatch incidents, context leakage and attributed provider cost; targets require a measured baseline. **Near term:** one shared task-provenance guide and stop/recovery tests. **Long term:** stable model-independent delegated-work platform with independently accepted execution environments.

## 2. Product and Engineering

**Mission.** Turn clear human intent into useful, maintainable software whose behavior can be inspected and tested.

**Mandate and responsibilities.** Own dashboard/API/Mac/Android product experience, registered engineering workflows, repository profiles, validation, integration and release preparation. Translate briefs into acceptance criteria, preserve accessibility, and maintain documentation impact maps.

**Assets.** Engineering runtime/orchestration/integration/delivery and project sessions; shared/config packages; React/Vite UI; Electron/Swift helpers; Kotlin/Compose app; CI. **Human leaders:** Head of Product, Principal Engineer and QA Lead. **AI roles:** backend/frontend/data/mobile/native/infrastructure implementers, testing/security/review/documentation/release specialists. **Expertise:** product discovery, application architecture, safe coding workflows, test design, native permissions and delivery operations.

**Rights and deliverables.** Own product backlog and candidate quality; request capability/profile changes through governance; independent approval required for consequential merge/release paths. Deliver reviewed diffs, validation receipts, local previews, operational runbooks and release evidence. A preview does not count as production deployment.

**Dependencies/access.** Core runtime, Security, Intelligence context and approved Client Solutions briefs. Read only granted repositories and project documents. No unrelated client source, production credentials, broad company financial records or automatic public publishing authority.

**Collaboration/measures.** Brief → acceptance review → scoped worktree → implementation/checks → independent review → guarded merge → release decision. Measure accepted changes, escaped defects, recovery burden, validation reproducibility and owner intervention. **Near term:** trusted-Mac delivery acceptance and Android build/device tests. **Long term:** dependable engineering across reviewed local/cloud runtimes without expanding arbitrary execution.

## 3. Machine Intelligence Lab

**Mission.** Learn which forms of intelligence make work more trustworthy, and publish only what careful evidence supports.

**Mandate.** Evaluate routing, deterministic understanding, retrieval, context composition, agent collaboration and safe adaptation; propose AthenaCoder/dataset/distillation research after scope and rights are defined. It does not own production policy or auto-deploy learned behavior.

**Assets.** `ai/benchmark/`, context/economics, local AI, corpus, memory/learning/reflection/skill evolution. These are evaluation substrates, not proof of training research. **Human roles:** Research Director, Evaluation Scientist, Data Steward. **AI roles:** evidence synthesizer, ML/RAG reviewers, experimental analyst and replication reviewer. **Expertise:** experimental design, ML systems, statistics, retrieval evaluation, privacy and reproducibility.

**Rights/deliverables.** Choose approved offline hypotheses/metrics, curate licensed consented data, recommend changes. Deliver preregistered protocols, versioned corpora, negative results, reproducibility packages and promotion recommendations. Production changes remain separately reviewed.

**Access/dependencies.** Approved datasets, synthetic tasks and redacted measurements only; Security reviews data boundaries, Core supplies runtime versions, Engineering supplies reproducible harnesses. No credentials, private reasoning, default client data, unreviewed raw captures or cross-company training reuse.

**Pathway/measures.** Research proposal → dataset/rights review → bounded compute approval → blinded/held-out evaluation → replication → reviewed publication. Measure reproducibility, held-out validity, safety regressions and cost/quality tradeoffs. **Near term:** intent non-execution and retrieval-scope benchmark. **Long term:** measurable model-independent orchestration science; no promised novel model or benchmark superiority.

## 4. Quantum Systems Research

**Mission.** Approach frontier computation with intellectual courage and unusually careful standards of proof.

**Status.** Proposed exploratory program; no dedicated quantum algorithms, simulator/hardware adapters, notebooks or experimental results were located. Incidental quantum questions in conversation tests are not research assets.

**Mandate/responsibilities.** Begin with literature review, feasibility and reproducible classical simulation; decide whether a research program is justified. **Assets:** general governed research/evidence infrastructure only. **Human roles:** Quantum Research Lead and independent scientific advisor. **AI roles:** bounded literature analyst, mathematical reviewer and reproducibility assistant. **Expertise:** quantum information, linear algebra, algorithms, numerical methods, scientific software and experimental uncertainty.

**Rights/deliverables.** Propose hypotheses and reviewed simulator experiments; no hardware account/spend authority without separate approval. Deliver annotated primary-source map, problem-selection rationale, resource model and replication protocol. No claim of advantage, patents, hardware partnerships or physical experiments.

**Access/dependencies.** Public/licensed research and approved synthetic code; depends on Intelligence Lab for evaluation, Engineering for safe compute, Governance for publication/IP. Prohibit unrelated company/private client data, infrastructure secrets and unreviewed remote execution.

**Pathway/measures.** Literature replication first, advisory review second, bounded compute experiment third. Measure correctness, reproducibility and feasibility; report inconclusive/negative outcomes. **Near term:** founder-approved question and feasibility charter. **Long term:** only pursue a focused specialty if evidence and expertise justify it.

## 5. Brand and Creative

**Mission.** Give Athena a recognizable voice and form that earn trust through clarity, craft and truthful ambition.

**Mandate/responsibilities.** Own approved narrative, terminology, visual direction, asset provenance and creative review. **Current assets:** brand reviewer/content identities, dashboard design system and review-only launch-package contract in `launch-workflow/`. **Missing assets:** verified image/video production adapter, canonical approved asset library and complete creative delivery path.

**People/AI/expertise.** Creative Director and Brand Editor; content strategist, brand reviewer and documentation specialist; identity design, typography, accessibility, writing and rights management.

**Rights/deliverables.** Approve proposed style/narrative within delegated human remit; cannot authorize product claims, external publication or spending alone. Deliver versioned brief, voice rules, asset manifest with rights/provenance, approved templates and disclosure-reviewed copy.

**Access/dependencies.** Approved product facts from Engineering and evidence register, research claims reviewed by labs, positioning approved by founder. No private customer names, unreleased security details, source dumps or unsupported performance claims. Start contributors on an approved public brief and synthetic creative exercise.

**Measures/opportunities.** Review consistency, accessibility, factual-claim traceability, rights coverage and rework; no invented brand-awareness uplift. **Near term:** versioned brand system and asset rights register. **Long term:** coherent creative operations with governed generation/export tools and human art direction.

## 6. Marketing and Growth

**Mission.** Connect useful capabilities with people who need them, without outrunning the evidence.

**Mandate/responsibilities.** Positioning, research-informed campaigns, draft copy, channel plans, analytics interpretation and experiments. **Current assets:** marketing/content/growth catalog roles, objective/experiment records, launch review packages and conditional test/read analytics adapters. **Human roles:** Marketing Lead and Growth Analyst. **AI roles:** market researcher, content strategist, growth analyst and brand reviewer. **Expertise:** audience research, communication, experimentation, measurement and ethical distribution.

**Rights/deliverables.** Recommend budgets/channels and prepare reviewable campaigns; no automatic spend/publication authority. Deliver approved campaign brief, factual claim map, draft content, consent-aware measurement plan and post-campaign evidence report.

**Access/dependencies.** Approved product/research statements, aggregate authorized analytics and approved brand assets. No unrestricted audience personal data, raw email/customer records, source code or confidential client strategy. Client campaigns require explicit separate project scope.

**Collaboration/measures.** Research → brief → creative → factual/security review → exact publish/spend approval → verified outcome. Measure observed conversions with lineage, approved experiments and cost, distinguishing attribution assumptions from facts. **Near term:** one finite draft-to-review workflow and GA4 grant alignment. **Long term:** governed distribution and trustworthy experiment feedback after real adapter acceptance.

## 7. Community and Partnerships

**Mission.** Build a community where contributors understand the work, its boundaries and the value of their contribution.

**Status/assets.** Recommended division; no dedicated community moderation/CRM/partnership lifecycle implementation established. General agent collaboration and documentation are useful substrate.

**Mandate.** Contributor/research onboarding, public education, feedback triage, collaboration proposals and responsible disclosure intake. **Human roles:** Community Steward and Partnerships Lead. **AI roles:** documentation, evidence synthesis and onboarding specialists. **Expertise:** technical communication, moderation, relationship management, licensing and research collaboration.

**Rights/deliverables.** Recommend collaborators and scoped projects; cannot grant account/repository access or promise contracts. Deliver collaboration briefs, contributor guide, reviewed events/materials and partner due-diligence records.

**Access/dependencies.** Approved public/internal onboarding documents and purpose-limited collaborator metadata. Governance approves invitations, Security approves access, labs define research tasks, Engineering supplies scoped issues. Prohibit confidential roadmap, client records and broad source access by default.

**Pathway/measures.** Interest → bounded task/mentor → rights/confidentiality review → time-limited invitation → acceptance review → offboarding. Measure completed contributions, time to useful onboarding, retention with consent and access-review completion. **Near term:** contributor pathways and external-collaborator policy. **Long term:** evidence-led ecosystem without uncontrolled tool/plugin installation.

## 8. Client Solutions

**Mission.** Apply Athena's capabilities to a client's concrete problem with clear commitments, careful boundaries and verifiable outcomes.

**Status/assets.** Company scoping, objectives, data bindings, workflow and engineering delivery exist; no client roster, contracts, revenue or service performance is established.

**Mandate.** Discovery, solution design, project acceptance, client-specific data classification and handover. **Human roles:** Solutions Architect, Delivery Lead and designated client sponsor. **AI roles:** account research, proposal, onboarding, implementation and independent acceptance reviewers. **Expertise:** requirements engineering, integration architecture, privacy, delivery and domain knowledge.

**Rights/deliverables.** Propose scope/service terms for human authorization; no agent may bind legal agreements or reuse client data. Deliver statement of work, scoped access map, acceptance protocol, evidence-backed handover and support/retention plan.

**Access/dependencies.** Only assigned company/project records, explicitly granted repository/tool bindings and approved client documents. No another client's data, founder private memory, secret values or model-training reuse without separate rights. Security reviews every data flow; Product owns feasible capability claims; Governance owns contractual/access decisions.

**Pathway/measures.** Qualification → scope/rights → isolated test project → verified pilot → human acceptance → handover/offboarding. Measure accepted outcomes, defects, recovery, scope variance and evidence completeness. **Near term:** synthetic pilot with no real customer data. **Long term:** repeatable bounded solutions, with tenant isolation independently accepted before broader collaboration.

## 9. Organizational Governance

**Mission.** Keep Athena's ambition answerable to the people affected by its decisions.

**Mandate.** Constitution, human decision rights, classification, access lifecycle, publication approval, research ethics, conflicts and audit review. **Current assets:** identity, policies, digest-bound approvals, company memberships, audit and Agent Society advisory records. **Human roles:** Founder/Accountable Owner, Governance Steward and independent reviewer. **AI roles:** risk coordinator, privacy reviewer and evidence clerk. **Expertise:** organizational design, security governance, documentation and applicable legal expertise supplied by qualified humans.

**Rights/deliverables.** Humans approve mandates, exceptions, access and public claims through explicit workflows. Prohibited operations cannot be legalized by a software approval. Deliver decision-rights register, review calendar, exception log, constitution and access-review evidence.

**Access/dependencies.** Minimum governance metadata and scoped evidence from each division; sensitive content requires separate clearance. Prohibit bulk private prompts, raw credentials, unrestricted client documents and hidden reasoning. Auditors need bounded read-only evidence, not execution privileges.

**Pathway/measures.** Decisions carry sponsor, rationale, scope, evidence, expiry and reviewer. Measure review timeliness, expired-grant closure, unresolved exceptions and evidence freshness. **Near term:** approve this source-material taxonomy and Organization Control design. **Long term:** accountable multi-human governance with explicit legal/organizational structure when the founder establishes it.

## 10. Security and Infrastructure

**Mission.** Make the safe path the reliable path, and make unknown security state stop work visibly.

**Mandate.** Threat modeling, trust boundaries, environment validation, device transport, secret-reference handling, build integrity, observability, recovery and incident response. **Assets:** security middleware, policy/approval/replay stores, signed execution, reviewed native runtime, deployment recipes, CI, telemetry and stop paths. **Human roles:** Security Lead and Infrastructure/SRE Lead. **AI roles:** security/privacy reviewers, network architect and incident coordinator. **Expertise:** application security, cryptography integration, tenant isolation, containers, databases, native permissions and operational response.

**Rights/deliverables.** Recommend/control reviewed security policy and emergency containment under human mandate; never allow `sudo`, arbitrary administration or secret collection by agents. Deliver threat register, security acceptance, restore drills, release gate evidence and incident runbooks.

**Access/dependencies.** Bounded configuration posture, redacted telemetry and scoped source evidence; secret manager metadata only. No default customer content or ability to extract private keys. Every division depends on this review; Security depends on Engineering's operable implementations and Governance's authority model.

**Pathway/measures.** Start with a fixture-based denial/recovery exercise; add production duties only after authenticated human authorization. Measure denied-unknown coverage, revocation propagation, restore success, unresolved critical risks and audit leakage. **Near term:** PostgreSQL/Mac acceptance and cloud containment decision. **Long term:** independently reviewed resilience and security without fragmented execution paths.
